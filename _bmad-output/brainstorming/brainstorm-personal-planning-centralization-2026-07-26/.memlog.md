- (idea by coach) Because there is no cloud sync, add a backup freshness indicator and remind only inside the app when the last export is stale.

- (technique) started Impact–Effort convergence
- (insight) Centralization is primarily one capture loop, one linking model, and one review loop; it does not require storing every specialist datum.
- (insight) Data durability is a prerequisite feature: the more life data the app owns, the more damaging local-only loss or migration failure becomes.
- (insight) The highest-leverage additions are shared infrastructure—Inbox, Areas/Projects/Goals, Search, Daily Brief, and Weekly Review—not more isolated trackers.
- (decision) Foundation first: verified build/test, iOS target alignment, versioned migrations, consistent save errors, and export/restore.
- (decision) First product layer: universal Inbox plus global search and destination-specific deep links.
- (decision) Second product layer: Areas, Projects, Goals, and lightweight links to existing tasks, events, assignments, certifications, workouts, and logs.
- (decision) Third product layer: focused Today brief, guided weekly review, recurring templates, and planned exception modes.
- (direction) Only after the shared operating layer works should Linkerworks add journal/mood/sleep metrics, finances, household inventory, relationship follow-ups, or experiments.
